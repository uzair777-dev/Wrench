## 1\. Introduction

### 1.1 Purpose

[Wrench](https://github.com/uzair777-dev/Wrench) is a free and open-source, native Linux desktop Git client targeting feature parity with GitHub Desktop (simplicity, PR-centric workflow), GitKraken (visual branch graph, forge integrations), Sublime Merge (speed, line history, worktrees), and Lazygit/GitButler (stacked branches, interactive bisect, granular staging), built with Qt/PySide6. It targets KDE Plasma users first, and works equally well on GNOME and other desktop environments via Flatpak. "Plasma-first" here means target audience and visual polish, not a framework dependency — see §2.3/§3.12 for why the app uses plain Qt widgets rather than KDE Frameworks.

### 1.2 Scope & Core Product Philosophy: We Do Not Forget the User

Wrench manages local Git repositories end-to-end: repository creation/cloning, staging and committing, branching and merging, remote synchronization over SSH/HTTPS, and forge-native collaboration (pull/merge requests, issues, CI status) across the confirmed v1 backend set — GitHub, GitLab, Forgejo/Gitea (including self-hosted instances), and Bitbucket Cloud. The forge integration layer in [src/wrench/forge](https://github.com/uzair777-dev/Wrench/tree/master/src/wrench/forge) is built as a capability-based, entry-points plugin architecture (adapters register themselves via Python packaging entry points against a shared capability interface) so additional backends can be added — by the project or the community — without redesigning the core app (see §3.6 and §7.1 for the full extension roadmap).

**Total User Sovereignty & Zero-Impact Feature Toggleability (Mandatory Across v1 and v2+):** Every single part of Wrench — whether already implemented in v1 or scheduled for v2 and beyond — **must be tweakable and toggleable from the Settings / Preferences menu** (both globally and with per-repository overrides where applicable). If a user does not like a feature, panel, badge, background daemon, safety net, or workflow, they can turn it off in Settings with **little to no runtime, memory, or visual impact**:

1. **UI Unmounting / Hiding:** When a feature is disabled in Settings, its tabs, sidebar sections, toolbar buttons, context-menu entries, gutter overlays, and status badges are immediately hidden (`setVisible(False)` or unmounted) without leaving dead space or broken layouts.  
2. **Backend Short-Circuiting (Zero Overhead):** When a feature is disabled, its background workers, timers, `inotify` watchers, subprocess calls, `pygit2` computations, and network `httpx` requests are completely bypassed at the `core.engine` / `forge.registry` entry point before any CPU, I/O, or memory cost is incurred.  
3. **Granular Parameter Tweaking:** Every enabled feature exposes its operational parameters (debounce intervals, commit batch sizes, font sizes, graph lane widths, snapshot retention counts, timeout limits, path templates) in a searchable Settings UI with a 1-click "Reset to Default" per setting and per category.  
4. **Auto-Save with Delta-Only Settings Undo/Redo (`FR-8.12`, `ui-planning.md §5.5 OPT-2/OPT-3`):** Settings auto-save with a `150ms` debounce and record **only the changed key delta `(key, old_val, new_val)`** into a bounded ring buffer (`settings_undo_log`), giving users instant `Ctrl+Z` / `Ctrl+Y` and out-of-order history revert inside Settings if they make a mistake.

### 1.3 Definitions

| Term | Meaning |
| :---- | :---- |
| **Forge** | A centralized, enterprise, patch-driven, or decentralized Git hosting/review platform (GitHub, GitLab, Codeberg, Forgejo/Gitea, Bitbucket, SourceForge, Azure Repos, Radicle, Gerrit, SourceHut, Tangled) |
| **MR/PR** | Merge Request (GitLab/Forgejo) / Pull Request (GitHub/Bitbucket) — used interchangeably |
| **Secret Service** | freedesktop.org D-Bus API for credential storage (backed by GNOME Keyring or KWallet) |
| **Portal** | XDG Desktop Portal — sandboxed apps' mediated access to host resources (`org.freedesktop.portal.Secret`, `FileChooser`) |
| **Settings Registry** | Centralized typed configuration and feature-gate manager (`src/wrench/storage/settings_registry.py`) governing every v1 and v2 feature toggle and parameter |
| **Delta Settings Snapshot** | A lightweight record storing only `(key, old_value_json, new_value_json, repo_path)` whenever a setting changes, enabling instant `Ctrl+Z` undo without copying the full settings table |
| **Zero-Impact Disable** | Architectural guarantee that disabling a feature in Settings both hides its UI surfaces and short-circuits its background threads/queries so it consumes zero CPU/network/RAM |
| **Stacked Branches** | A chain of dependent feature branches where rebasing or amending an earlier branch automatically updates downstream branches via `git rebase --update-refs` |
| **Worktree** | A linked working tree created via `git worktree` sharing the object database of a parent or bare repository |
| **Rerere** | Git's "reuse recorded resolution" (`git rerere`) engine that caches conflict resolutions and auto-applies them when identical conflict hunks recur |

## 2\. Overall Description

### 2.1 User Personas

- **The Visual Developer (Primary):** Wants a clean graph, clear staging, visual conflict resolution, and one-click PR reviews without memorizing complex `git log --graph`, `git rebase -i`, or `git bisect` flags.  
- **The Minimalist / Classic Linux User:** Wants a fast, no-nonsense local staging and commit GUI and wants to turn off forge integrations, CI polling, safety stashes, system tray icons, or stacked-branch UI completely so Wrench runs as a pure, ultra-lightweight local Git client.  
- **The Linux Power User:** Demands native performance, low memory footprint (\<250MB RSS), system theme/accent compliance, SSH agent and GPG/SSH signing support, custom keyboard-driven actions, and deep tweakability of every internal threshold and behavior.  
- **The Open-Source & Monorepo Contributor:** Frequently switches between GitHub, GitLab, and self-hosted Forgejo instances, works with stacked PRs or patch series (`git format-patch`), and needs partial clone / sparse-checkout support for large repositories.

### 2.2 Operating Environment

- **Target OS & Architectures:** Linux (`x86_64`, `aarch64`), Flatpak sandbox (primary delivery mechanism via [packaging/](https://github.com/uzair777-dev/Wrench/tree/master/packaging)), AppImage (secondary), native distro packaging (Arch AUR / Debian / Fedora COPR in v2 `VP-15`).  
- **Runtime Stack:** Python 3.11+, `PySide6` (Qt 6.8+), `pygit2` (`libgit2` C bindings), system `git` CLI (2.38+), `httpx` (HTTP/1.1 & HTTP/2), `secretstorage`, `watchdog`, and SQLite (`~/.local/share/wrench/wrench.db` via `platformdirs`).

### 2.3 User Interfaces

- Native Qt 6 GUI in [src/wrench/ui](https://github.com/uzair777-dev/Wrench/tree/master/src/wrench/ui) using standard widgets styled dynamically via system palette/KStyle rather than hard-linking KDE Frameworks.  
- Searchable, categorized **Settings & Feature Toggle Dialog (`Ctrl+,`)** with instant live-apply signals (`setting_changed`), per-repository override tabs, JSON export/import of preferences, and "Minimalist Mode" / "Power User Mode" presets.

## 4\. Non-Functional Requirements (NFRs)

- **NFR-1 (Performance):** Repository load \< 500ms for 10,000 commits; \< 1.5s first paint on 100,000+ commit monorepos using `.git/objects/info/commit-graph` and lazy viewport slicing; DAG commit graph rendering at 60fps scrolling; memory footprint \< 250MB RSS baseline (and \< 140MB RSS when optional forge/watcher/signing features are toggled off in Settings).  
- **NFR-2 (Reliability & Non-Destructive Safety):** Zero silent data loss — every destructive write (`reset --hard`, `rebase`, `stash drop`, `clean`, `bisect reset`) is preceded by a `git stash create` safety snapshot in `core/snapshots.py` (unless explicitly disabled by the user via `safety.pre_op_snapshot.enabled = False`). Clean repository disconnect/uninstall (`FR-8.2`) removes any Wrench-specific metadata without breaking standard CLI `git` workflows ([GitButler \#14491](https://github.com/gitbutlerapp/gitbutler/issues/14491)).  
- **NFR-3 (Security):** Forge tokens, OAuth sessions, and GPG/SSH passphrases stored exclusively in D-Bus Secret Service (`secretstorage` / KWallet / GNOME Keyring) or XDG Secret Portal inside Flatpak (`src/wrench/credentials`). Zero plaintext credentials written to `~/.local/share/wrench/wrench.db`.  
- **NFR-4 (Usability & Accessibility):** Full keyboard navigation across all primary flows (staging, hunk stepping, committing, switching tabs, `Ctrl+K` command palette) and explicit visual summaries before executing destructive Git operations.  
- **NFR-5 (Total User Configurability & Zero-Impact Feature Disabling):** Every feature, UI component, visual indicator, and background task in Wrench (both v1 and v2+) must be controlled by an explicit setting in `SettingsRegistry` (`src/wrench/storage/settings_registry.py`) and exposed in the Settings menu (`Ctrl+,`). Disabling any feature must:  
  1. Take effect **immediately at runtime** via Qt signals without requiring an application restart.  
  2. Hide all associated UI elements cleanly without empty placeholder gaps or broken layouts.  
  3. Short-circuit all associated background threads, timers, filesystem watches, and subprocesses so disabled features incur **zero CPU, disk I/O, or network overhead**.  
- **NFR-6 (Zero-Shortcut Security & Optimization Enforcement — `SEC-1`..`SEC-7` & `OPT-1`..`OPT-8`):** Coding executors MUST NOT trade away security or performance optimizations to shorten development time. Every phase is gated by an automated static/AST verification suite (`tests/meta/test_no_shortcuts_guard.py`) enforcing: (`SEC-1`) `shell=False` and mandatory `--` end-of-options delimiters before refs/paths to block Git argument injection; (`SEC-2`) strict URL scheme allowlisting (`https://`, `ssh://`, `git@`) and SSRF loopback blocking on mirror/forge URLs; (`SEC-3`) automatic token/credential redaction in all logs and UI drawers; (`SEC-4`) `0o600` permissions on temporary askpass/rebase files; (`SEC-5`) 100% parameterized SQLite queries (`?` placeholders only); (`SEC-6`) allowlist-validated `wrench://` help URIs; and (`SEC-7`) zero `TODO`/`pass`/`NotImplementedError` stubs.

## 5\. System Architecture Overview

As defined in [ARCHITECTURE.md](https://github.com/uzair777-dev/Wrench/blob/master/ARCHITECTURE.md), Wrench enforces a strict 3-tier one-directional architecture governed by the centralized `SettingsRegistry`:

1. **UI Layer (`src/wrench/ui`):** `PySide6` widgets, custom `CommitGraphWidget` DAG painter, 3-way merge view, inline PR review overlay, blame/line-history panes, `SettingsDialog` (`Ctrl+,`), and `Ctrl+K` Command Palette. Never imports `pygit2`, `subprocess`, or `sqlite3` directly. All optional UI surfaces listen to `SettingsRegistry.setting_changed` to show/hide dynamically.  
2. **Façade Layer (`src/wrench/core/engine.py`, `src/wrench/forge/registry.py`, `src/wrench/storage/settings_registry.py`):** Thread-safe orchestration, feature-gate checking (`settings.get_bool(...)`), pre-operation safety snapshots (`core/snapshots.py`), background worker dispatch (`ui/workers.py`), and capability-checked forge routing (`forge/capability.py`).  
3. **Low-Level Backends:**  
   - `core/read_ops.py`: Fast in-process `pygit2` reads (`status`, `diff`, `log`, `blame`, `reflog`, signature check).  
   - `core/write_ops.py`: Subprocess system `git` CLI writes (`commit`, `rebase --update-refs`, `worktree`, `bisect`, `sparse-checkout`, `stash --staged`, `rerere`, `format-patch`, `am`, hook runner with login-shell `PATH` injection).  
   - `forge/adapters/`: Capability-based clients for GitHub, GitLab, Codeberg, Forgejo/Gitea, Bitbucket, SourceForge, Azure Repos, Radicle (`rad://` / COBs), Gerrit (`refs/for/` & `/a/changes/`), SourceHut (`sr.ht` GraphQL), and Tangled (`atproto` Knots & Spindles).  
   - `storage/`: Version-migrated SQLite database (`wrench.db`) storing global settings, per-repository setting overrides, recent repos, saved sessions, custom actions, and ETag-cached forge metadata.

## 7\. Assumptions & Decisions Log

| Decision ID | Status | Summary & Rationale |
| :---- | :---- | :---- |
| **DEC-1** | ✅ Confirmed | **Hybrid `pygit2` \+ `git` CLI split:** Use `pygit2` in `core/read_ops.py` for low-latency graph, diff, reflog, and blame reads; delegate all mutations, hooks, rebases, worktrees, and bisect flows in `core/write_ops.py` to system `git` (2.38+) for 100% compatibility with user `.gitconfig`, hooks, and SSH/GPG agents. |
| **DEC-2** | ✅ Confirmed | **Stacked branches via native `git rebase --update-refs`:** Rather than inventing proprietary virtual-branch metadata that can corrupt standard CLI git repos ([GitButler \#5758](https://github.com/gitbutlerapp/gitbutler/issues/5758), [GitButler \#14491](https://github.com/gitbutlerapp/gitbutler/issues/14491)), Wrench implements stacked branches on top of standard Git refs and `git rebase --update-refs`, storing stack parent relationships non-invasively in SQLite (`wrench.db`). |
| **DEC-3** | ✅ Confirmed | **Login-shell `PATH` hydration for Git Hooks:** GUI apps launched via `.desktop` files or Flatpak on Linux often miss user runtime managers (`nvm`, `fnm`, `pyenv`, `mise`, `cargo`), causing Husky/pre-commit hooks to fail ([GitHub Desktop \#17385](https://github.com/desktop/desktop/issues/17385), [GitHub Desktop \#21317](https://github.com/desktop/desktop/issues/21317)). Wrench resolves and caches the user's interactive login shell `PATH` at startup (`$SHELL -lic 'env'`) when `hooks.hydrate_login_shell_path` is enabled, while offering an explicit `--no-verify` toggle ([GitHub Desktop \#11802](https://github.com/desktop/desktop/issues/11802)). |
